# 実装と運用

## main/PR系統

公開対象は `site/` の静的HTML/CSS/Vanilla JavaScript。READMEでは61HTMLページと記載。`data/` は正本、`tools/` は生成・検査、`docs/` は履歴と運用、`tests/` は診断テスト、`server/` は任意のPHPメール受け口です。公開物へ開発ツール・下書き・設定を丸ごと置きません。

| 作業 | コマンド |
|---|---|
| 診断データ生成 | npm run data |
| 36タイプ生成 | npm run types |
| トップタイプデータ | npm run atelier |
| ヒアリング生成 | npm run questionnaires |
| sitemap生成 | npm run sitemap |
| 見本制作プロンプト | npm run sample-prompts |
| 正本整合・内容検査 | npm run check |
| 診断テスト | npm test |
| ブラウザ検査 | npm run check:browser |
| 公開変更の予告 | npm run publish:dry |
| 公開値適用 | npm run publish:apply |
| 残る公開条件 | npm run publish:ready |

`type-*.html`、types、industries、診断データJS、sitemap、トップタイプデータ、ヒアリングページ等は生成対象。原則として正本と生成器を編集し、再生成します。生成対象ではない完成ページだけ手編集する方針です。

## 公開条件

main `data/publish-values.json` に公開値を入力。canonicalOriginはhttps://crewascent.com。事業者名、代表、住所、電話、メール、営業・返信、税・支払、ドメイン費、取消・返金、管轄、対応ブラウザ、方針日、外部処理者、保存・開示等が未入力のまま残ります。

legalReviewed=false、indexTypePages=false。公開値の空欄解消だけでなく、法務文面と実運用の確認が必要です。段階1は基本19ページ、段階2はタイプ37ページ（本文2,000字以上等の条件）。結果、404、works、相談2フォームは公開後も検索へ載せない方針。sitemapはindex対象だけ。法務コアの検査は3つの法務ページだけでなく関連コア4ページという条件もあり、正確にはpublish-stages.mjsを参照します。

publish:applyはnoindexやcanonicalも変える操作です。今回のナレッジ作成では実行していません。

## UIUX別案

ルートに全74HTML、contractsに8契約HTMLとMarkdown、Node.js24以降のサーバー。ローカルSQLite、SitesはWorkers+D1、DB定義はdb/schema.ts、移行履歴はdrizzle。通常ビルドはnpm run build、開発npm run dev、検査npm test/npm run check。`.local/crew.sqlite` と `.env.local` は収録しません。

管理者認証はパスワードと署名付きHttpOnly Cookie（8時間）、同一オリジン検証を使う設計。管理HTMLが読めることと個人情報APIの認可は別です。通常ビルドでupgrade.py等の一度限りの移行スクリプトを再実行しません。

予約は運営者が実在する空き日時を登録。日本時間、60分、定員1人、1時間以上先/1年以内、重複拒否、隣接可。予約で枠が消え、本人取消で戻る。ICSと本人取消リンクを提供。会議URL自動発行や本人確認付きリンク復旧は未実装。架空枠を初期投入しません。

Shopifyは4プラン×着手金/残金=8バリエーション。金額は40,000/60,000/75,000/110,000円ずつの2回。分割払い契約を自動発行するのではなく別注文。プライベートStorefrontトークンはサーバーだけに置く。署名・ショップ・通貨・価格・商品・数量・参照を検証するorders/paid Webhookで反映し、戻りURLだけで入金済みにしません。税・法務・商品・正式事業者等の条件がそろうまで停止。

Resend通知は未接続が初期。受付/予約/取消を顧客と運営者へ送る案。通知キューと手動再処理があり、定期自動再試行ジョブはなし。返金/チャージバックの自動同期や案件ごとの着手金・残金自動紐づけも範囲外です。
