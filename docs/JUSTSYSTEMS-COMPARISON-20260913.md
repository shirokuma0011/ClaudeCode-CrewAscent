# ジャストシステムとのUI/UX比較評価

評価日：2026年9月13日

## 結論

現在の改修版クルーアセントは、読みやすさと相談導線の基礎を整えた段階であり、ジャストシステムに並ぶブランド表現と品質の説得力にはまだ届いていない。総合の目安は、ジャストシステム85〜90点、改修版クルーアセント70〜75点。制作費1,000万円相当、2027年の最高品質という到達を現状から保証することはできない。

点数は今回の目視による主観的なヒューリスティック評価。知名度・売上・企業規模を直接加点していない。実際の利用者によるタスク成功率、問い合わせ率、表示速度、アクセシビリティ適合性を測定した点数ではない。旧版の約40点という評価とは対象バージョンが異なる。

## 比較条件

- ジャストシステム：[公式トップページ](https://www.justsystems.com/jp/)を実ブラウザーで確認。PC幅1280px、スマートフォン幅390pxで、トップと企業紹介部分を目視した。トップの製品切り替えも観察した。
- クルーアセント：改修版のローカル表示をPC幅1280px、スマートフォン幅390pxで確認。トップの文章・ナビ・料金・相談導線を確認し、制作見本ページと紹介ページのソースを補足した。
- 公開中の全下層ページ、実機iPhone/Android、決済完了、予約完了までを比較監査したものではない。クルーアセントの過去の機能検証と今回の比較評価は別の確認である。
- ジャストシステムは複数製品・サポート・企業情報・採用等への入口、クルーアセントは小規模事業者の制作相談が主目的。情報量の多さ自体を優劣とはしない。

## 最も大きな差

### 1. 提供するものが画面に現れているか

ジャストシステムは利用場面の写真を大きく見せ、製品名・製品画像・説明を組み合わせている。文章とビジュアルが同じ対象を説明するため、事業の具体像をつかみやすい。

クルーアセントのヒーローは、診断の思想を示す抽象図形が主役。Web制作を依頼したい人にとっては、完成サイトの見た目、スマホ画面、制作の幅を確かめる材料が不足している。制作例・見本の入口も主ナビにない。作品を確認したくなった瞬間の導線を強くしたい。

### 2. 品質を判断できる具体的な材料

クルーアセントには相談姿勢や進め方の説明があるが、読者がその品質を自分で判断する材料が弱い。「事業を理解する」「迷わない順番にする」を、実際の構成図、画面、変更理由で示す必要がある。

作品掲載時は、制作見本と顧客案件を明示的に区別する。見本であっても、想定した課題、設計上の判断、PC・スマホの完成画面を丁寧に示せば、設計力を確認する材料になる。架空の受注実績や成果数値を足す必要はない。

### 3. 事業紹介と診断のバランス

現在のトップは、診断を始めるボタンが最も目立ち、その後にも診断の説明が大きく続く。診断は独自性だが、制作を依頼する判断材料より先に長く見せることが最適かは未検証。

制作相談を増やす目的なら、価値の提示 → 制作例 → 制作範囲・料金 → 進め方 → 診断または相談、という構成を検討する。診断を必須の通過点と誤解させない。効果は公開後の利用状況で確かめる。

## ジャストシステムにも改善余地はある

- 自動切り替えと文字の出現演出は、情報が落ち着くまで読者を待たせる場面があった。演出を増やすこと自体を品質目標にしない。
- 写真に白文字を重ねるため、背景によって文字の見つけやすさが変わる。正式なコントラスト測定はしていない。
- スマホでは製品切り替えが小さいドット中心になり、PCの製品名一覧より次に何があるか分かりにくい。
- 「VIEW STORY」のような英語の操作ラベルは、クルーアセントの想定客には具体的な日本語のほうが適する可能性がある。

## 次に直す優先順位

1. **制作の品質を見せる。** 独自の制作見本を選び、トップ上部に完成画面と短い設計理由を掲載する。作品を見る導線を主ナビに設ける。
2. **ヒーローを事業の成果物と結びつける。** PC・スマホのサイト画面、情報整理の過程、診断との関係を一つのビジュアルにまとめる。6×6図形は補助モチーフとして活用できる。
3. **説明文を具体化する。** 「いい見た目には、伝わる理由がある。」に、どの情報をどう配置したかという図解を添える。「無料で、サイトの方向を見つける」は「無料のWeb診断を始める」等へ具体化し、相談との違いを伝える。
4. **トップの説明量を削る。** 診断・理念の重複を減らし、作品、料金、制作体制、相談方法へ進みやすくする。スマホは各セクションで判断材料が一つ増える構成にする。
5. **事業情報を確定する。** 実際の運営者情報、提供範囲、税区分などを確定する。公開準備の不足とUIの見た目は分けて管理する。
6. **改善を利用者で検証する。** 初見の想定客が「何を依頼できるか」「いくらか」「どんなものができるか」「次に何をすればよいか」を説明できるか確かめる。

今回の成果物は比較評価資料。サイトの追加改修・再公開は実施していない。
