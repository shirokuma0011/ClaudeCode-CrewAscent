## 1. バグ修正

`styles.css:1210`

## 2. UI/UX 改修（index.html を基準に下層を引き上げ）

### 2.1 下層ページの第一画面にあった 211px の空白

実測で、`services.html` は英字見出し「Services」と日本語見出しの間に
**211px の空白**がありました。原因は `.ah__inner` の `align-items: end` です。

```
.ah__enwrap  "Services"        top=158  高さ64
.ah__inner                     top=236  padding-top 49px   align-items:end
.ah__aside   要点表            top=285  高さ386      ← 高い方
.ah__main    見出し            top=384  高さ287      ← 下端に合わせて押し下げられる
```

左桁（見出し）が、右桁（要点表）の高さに合わせて**下端へ押し下げられて**いました。

`styles.css` の `.ah--decision .ah__inner`（詳細度が上）が
`align-items:end` を再指定していたため、詳細度をそろえて解除しました。

| ページ | h1 の位置（改修前 → 改修後） |
|---|---|
| services.html | y=433 → **y=334** |
| plans.html | y=432 → **y=334** |
| process.html | y=432 → **y=334** |
| management.html | y=407 → **y=334** |

**第一画面で見出しとリードと要点表が同時に読める**ようになり、
index.html（h1 が y=220）との落差が縮まりました。

### 2.2 章の英字と見出しを地続きにした

`.ah__en` の下マージンを詰め、要点表の開始位置を eyebrow の高さへそろえました。
英字見出しと本文が「別々の塊」に見えていたのを、ひとつの見出し面にしています。

### 2.3 追加した部品（第一画面のCTA用）

## 8. 追記: 正式ロゴの採用

### 8.1 それまでの状態

ヘッダーとフッターには、**上昇矢印と三点経路を省いた簡略SVG**が表示されていました

### 8.2 採用の方法

正式マークを、ヘッダー・フッター・ファビコンで使うようにしました（全21ページ・42箇所）。

`<img>` を2枚置くと両方を取得してしまいますが、背景画像なら
**実際に適用された方だけ**を取得します。実測でも、

- TOP（濃色ヒーロー上のヘッダー） → `logo-onink.webp` のみ取得
- 下層ページ（白いヘッダー） → `logo.webp` のみ取得
- 高精細ディスプレイ → `@2x` を取得（`image-set()`）

名前は `<a class="brand" aria-label="クルーアセント ホームへ">` が持っているため、
絵は装飾として扱えます（読み上げは変わりません）。

## 9. 追記: 記事への図解追加と、前回report の訂正

### 9.1 【訂正】「壊れたCSSは1件」は誤りでした。実際は100件

第1.1項で「4つのCSSすべてで括弧の対応を検査し、これ1件だけでした」と書きましたが、**誤りです。**

私の検査が `{` と `}` の**総数を数える方式**だったためです。今回の壊れ方は

```css
@media (min-width: 768px) { .band { padding-block: 68px; } {}}
```

のように `{}`（セレクタの無い空規則）が入るもので、`{` が1個・`}` が1個増えるため
**総数では釣り合ってしまい、検出できません**でした。

検査を**入れ子の深さを追う方式**へ改め、あらためて数えた結果:

| ファイル | 件数 |
|---|---|
| **styles.css** | **100件**（`} {}}` が85件、改行を挟む形が15件） |
| base.css / system.css / top.css | 0件 |

すべて修正し、4ファイルとも「深さが0で閉じる／過剰な閉じ括弧なし／セレクタの無い規則なし」を確認しました。

表示への実害はありません（ブラウザは空規則を読み飛ばすため）。
ただし「検査したから大丈夫」と報告した根拠が誤っていたので、訂正します。

### 9.2 【訂正】横スクロールの検査方法も不十分でした

`document.documentElement.scrollWidth - innerWidth` で測っていましたが、
このサイトは `body { overflow-x: hidden }` を敷いているため、
**はみ出しがあっても scrollWidth は増えません**。つまり
「切り落とされて見えない要素」を検出できない方法でした。

**要素の右端を1つずつ測る方式**へ改めました。判定は次のとおりです。

- `position: fixed` の要素は対象外
- 横スクロールできる箱（`overflow-x: auto/scroll`）の中は、到達できるので対象外
- それ以外で画面幅を超えるものを「はみ出し」とする

**21ページ × 7画面幅（320/360/390/768/1024/1440/1920）= 147通り**を測り直しました。

| 結果 | |
|---|---|
| はみ出し | **index.html の `div.arch` のみ** |
| 判定 | **設計どおり**。ヒーローの6×6骨格を `overflow:hidden` の中で意図的に画面より大きく置いている装飾 |

実害のあるはみ出しは0でした。前回の結論自体は変わりませんが、根拠を測り直しています。

## 12. 追記: 再評価で見つけた2件と、その修正

### 12.1 【実バグ】診断を始めても、設問が画面の外にあった

「16問で診断を始める」を押した直後の画面に、**設問が1問も映っていません**でした。

| 画面幅 | 押した直後の位置 | 最初の設問の位置 | 見えている設問 |
|---|---|---|---|
| 390px | スクロール1676px | 画面の**1170px上** | **0問** |
| 1280px | スクロール1144px | 画面の726px上 | 6問中2問 |

390pxでは、画面に出るのは「前へ／次へ／最初からやり直す」とフッターだけです。
上へスクロールし直さないと、答えられません。

**原因**: 開始処理が `renderPage(false)` を呼んでおり、**位置合わせを一切していません**でした。
開始ボタンはモード比較カードの中、つまりページのかなり下にあります。
押すと案内文が消えて紙面が縮みますが、スクロール位置はそのまま残るため、
設問の並びを通り越した位置に取り残されます。

**修正**: 診断領域の先頭へ位置を合わせる `scrollToQuizTop()` を追加し、
開始時とページ送り時の両方で呼びます。紙面の一番上（`top: 0`）ではなく
**診断領域の先頭**に合わせています。進捗バーと座標欄が上に貼り付く作りなので、
その二つが自然な位置に来る場所が正解です。

修正後は 390px / 1280px のどちらでも、開始直後に設問が見えます。

### 12.2 「動きを減らす」設定の取りこぼし

OSで「動きを減らす」を選んでいる場合、これまで止まっていたのは
出現アニメーションだけで、**95か所の transition が残っていました**（実測）。
ヘッダーの切り替え、開閉の矢印、画像の拡大などです。

### 21.2 方針: 「座標の設計事務所」

このサイトが他と違うのは、6×6の座標マップという**独自の考え方の道具を持っている**ことです。
それを飾りではなく identity として扱い、他の装飾はすべて引きました。

### 21.3 実装の形

**`site/assets/css/crew.css`** を1本追加し、全59ページで**最後に読み込む**形にしました。

- 各ページのHTMLからは、装飾専用だった要素（`.gridlines` `.arch` `.ah__enwrap` `.opener__en` `.chapidx`、章の「Chapter」表記）を取り除きました。**本文・リンク・見出しの階層は変えていません**
- トップのヒーローだけは組み替え（`.hero2`）。それ以外のページは構造そのまま
- 生成器（`tools/generate-type-pages.mjs`）からも同じ装飾要素の出力を外し、36タイプページを作り直しました
