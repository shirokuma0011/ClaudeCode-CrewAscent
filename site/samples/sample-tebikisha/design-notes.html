「小さなお店のレジと予約の導入代行 てびき舎」の設計メモ

この見本は架空の事業です。Web診断36の CA02 先進案内型サイト の方針を、業務システム導入の事業に当てはめるとどうなるかを示すために作りました。トップと「相談の申し込み」の2ページです。

01このタイプの方針

新しいサービスの使い方を、迷いの少ない案内で届けるタイプです。内容は新しいが、利用者には分かりやすく説明する必要がある事業に向きます。ステップ、対象者別の入口、デモ、FAQを組み合わせ、未知のサービスへの不安を減らします。

位置実用・情報 × 先進・新しさ
横軸 2 / 6（情報寄り）— 分かりやすい案内
縦軸 6 / 6（もっとも先進寄り）— 未来感と実験性
デザインの言葉クリーンナビゲーション重視ラインモーション明るい先進色整った余白
この見本の考え方業態ごとに違う「入れ替えの順番」（食堂・雑貨店・教室）を、3本の路線が並ぶ路線図として見せる。さらに、最初の画面の下端から「次の駅」まで一本の線を通し、いま何番目の段階を読んでいるかを、どの画面でも分かるようにする。

02最初の画面の4つの役割と、この見本での答え

方針この見本では
見出しの役割
誰のための、何を助けるサービスかを平易な言葉で伝える		「レジと予約を、お店の順番で入れ替える。」の一文と、その上の「小さなお店の、レジと予約の導入代行」。専門用語を使わずに、小さなお店のレジと予約を入れ替える仕事だと言い切りました。
添える情報
対応内容、相談方法、料金の入口を短く示す		見出しの下に、対象（従業員5人以下の食堂・雑貨店・習い事教室）／頼めること（機種選び・設定・操作の説明）／料金（相談は無料・設定作業 1回 16,500円〜（税込））の3行。料金は金額まで書き、3秒で「いくらか」まで分かるようにしました。
裏づけ
受付の流れ、対応範囲、よくある質問など、依頼前に確認できる事実を置く		最初の画面の下端に、相談→機種の提案→設置と設定→練習と本番の4つの駅を、案内の青の線で横に通しました。各駅に所要の目安を添え、押すと「導入の流れ」の同じ駅へ進みます。左には「早ければ3週間」。
主な行動
「相談の流れを見る」を主要な行動として置き、その近くに現在対応できる範囲、相談の流れ、決まっていない段階でも相談できることを添える		「相談の流れを見る」を薔薇色のボタンにして、見出しの下・ヘッダー・スマホの下部に置きました。スマホの下部の固定ボタンは、最初の画面のボタンが画面の上へ抜けてから出し、同じ役目のボタンや「導入の流れ」の章が見えている間は隠します（重ならないように）。すぐ下に「決まっていない段階でも相談できます。いま対応しているのは、レジ・カード決済・ネット予約の3つです」。2つめの行動「相談フォームへ進む」は文字リンクで、下層の「相談の申し込み」へ進みます。

03情報の優先順位と、置いた場所

優先順位（方針）この見本で置いた場所
1. どんな人のためのサービスか最初の画面の3行と、最初の章「どんなお店のための支援か」。食堂・雑貨店・教室を3本の路線にし、各路線の駅名板にその業態の図を添えました。「近いお店を選ぶ」でその線だけを濃く見せます（選ばなくても全部読めます）
2. 何を依頼できるか2つ目の章「依頼できること・まだできないこと」。できること4つと、まだできないこと3つ（記帳の代行・機器の販売・常駐）を左右に並べています
3. 初めて利用する時の流れ最初の画面の下端の4駅と、3つ目の章「はじめての導入の流れ」。ページを通る線の上に4つの段階を置き、それぞれに所要の目安と「お店が用意するもの」を1行、使う場面の写真か図を同じ右側に4:3で置きました
4. これから実現したいこと3本の路線の「まず一つだけ → 2番目 → 3番目」。いきなり全部を替えず、どこから始めると無理がないかを業態ごとに示しています
5. 現在提供できること最初の画面の「いま対応しているのは、レジ・カード決済・ネット予約の3つ」と、2つ目の章のできること
6. 費用の考え方4つ目の章「費用の考え方」。リードは「てびき舎に払うのは、設定作業の料金だけです。」の1文にし、相談0円 → 設定作業16,500円〜（税込）の2駅を線の上に置きました。追加の費用が出る条件の表の横に、含むもの（練習2回まで）・含まないもの（機器の代金と月額は機器会社と直接契約）・税込の注記。同じ事実は1ページに1回だけ書いています
7. 問い合わせの方法と、その前に確認できること5つ目の章「よくある質問と相談の方法」と、線の終点「次の駅：相談の申し込み」。下層のページで、この後どうなるか（3駅）・フォーム・手元にあると早いものを示します

04見た目の判断

配色#F7F9FC 地の色（青みのある白）
#14213D 紺: 文字・罫線・フッターと、「導入の流れ」の章の地（写真と図が主役の章を1つだけ濃くし、前後の明るい章と対比を作る）
#3A86FF 案内の青: 線と駅だけ（小さな青い文字は同じ色相を濃くした #1B58C2）
#D23A70 薔薇色: 次に押すボタンだけ
#EDF2F9 淡い青: 下層の現在地の帯と、フォームの章の地
書体見出しは Noto Sans JP（Medium 500、小見出しとボタンは Bold 700）。料金・所要・駅の番号などの数字は Manrope（Medium 500）。どちらも SIL Open Font License の書体を、このサイトで使う文字だけに絞って fonts/ に置いています（ライセンス文は fonts/OFL.txt）。本文はOSのゴシックです。外部の書体サービスは読み込みません。丸ゴシックや極太は使いません
署名モチーフ「駅の線」: 案内の青の細い実線（PCで4px、スマホで3px）と、白い駅の輪。縦の線に輪を乗せるのは「導入の4段階」と「終点」だけにし、章の見出しには線の右に短い目盛りだけを置きました。番号つきの丸を並べると教材のように見え、「線の上の駅＝導入の段階」という意味もぼやけるためです。最初の画面の下端の4駅、3本の路線（小さな点）、料金の2駅、下層の現在地の帯、フォームの必須4項目、ヘッダーの路線図のナビ（2px）も、同じ線で描いています
骨格最初の画面は、左に見出しと3行の事実、右に画面の端までカウンターの図、下端に4駅の帯。そこから縦の線がページの左を通り、5つの章（対象 → 頼めること → 流れ → 費用 → 相談）の目盛りを順に通って、終点の「次の駅」のボタンで終わります。隣り合う章で形を変えています（駅名板つきの路線図 → 2列の一覧 → 線の上の4段と写真 → 運賃の2駅と表 → 問答と写真）。タブレットの幅では、最初の画面を2列にして、ボタンまで1画面に収めています
写真手元の写真（相談・提案・予約の手元）を、流れの段階の横（線の同じ右側に4:3、PCで約330×250px）と相談の章に、中くらいの大きさで置きました。細い帯に切ると手元が切れるため、4:3にしています。顔は写していません。予約画面の写真の画面は、この見本のための架空の画面で、画像の下にそう書き添えています（画像の上に重ねず、手元を隠しません）。3つの業態の図は1枚の画像を3本の駅名板に切り分けて使い、路線と図を同じ行で読めるようにしました
署名の動き読み進めた分だけ、ページを通る縦の線が上から濃い青で埋まっていきます（スクロールに合わせて伸びる。繰り返しの動きはありません）。下層のフォームでは、必須の項目が埋まるたびに、フォームの上の小さな線が伸びます。価格の数字は動かしません
動きを減らす設定では線ははじめから最後まで描かれた状態です。JavaScriptが動かない環境でも同じです
方針からの調整行動の色は方針の #E0457B を、白い文字で4.5:1を満たすよう少し濃くして #D23A70 にしました。「白または濃色を主役に」は青みのある白を主役にし、料金と表とフォームの章は明るい地にしています。濃い地は写真が主役の「導入の流れ」だけです。ページの高さはトップがPCで約5,400px、スマホで約7,300px、下層がPCで約3,400px、スマホで約4,900pxです（見本の枠を含む）

05下層ページ「相談の申し込み」

このページを選んだ理由このお店の主な行動は「相談の流れを見る → 相談フォームへ進む」で、相談の前の不安（何を用意するか・送ったあとどうなるか）を1枚で解くのが、いちばん申し込みに近いからです。
最初の画面h1 の上に「駅の現在地の帯」（案内を読む → いまここ：相談を申し込む → 相談 → 機種の提案 → 設置と設定 → 練習と本番）。その下の左に h1・リード・「フォームへ進む」、右にこのページの中身である「手元にあると早いもの」の図を正方形で置き、要点3つ（料金・書くこと・そのあと）は全幅の3列に並べました。トップとは、帯が上にあること、図が正方形で画面の端まで広げないこと、事実を罫線の一覧ではなく3列で見せることが違います。トップで使った写真は、このページでは使っていません
この後どうなるかフォームの上に、送る → 2営業日以内に日時の候補が届く → オンラインで30分、の3駅を、縦の線から横に出る線で1列に示しました（スマホでは縦の線の上に並べます）。申し込みも導入の駅の1つ（全6駅の2つ目）なので、下層にもトップと同じ線を通しています
フォーム必須は4つ（業態・困っていること・お名前・メール）。入力中は上の4駅が埋まり、足りないまま送るとエラーの一覧と各項目の言葉が出ます（メールの欄は、空のときは「書いてください」、形が違うときは「形を確かめてください」と分けています）。送ると「送信中」のあと見本のダイアログが出て、「この見本では、送信していません」と表示します。送れなかったときは、同じ部品で「送れませんでした。入力は消えていません。時間をおいて、もう一度お試しください。」と出し、入力を残したまま、もう一度押せるようにします（回線が切れているときに出ます。見本では 失敗したときの表示 で確かめられます）。フォームの横には「相談の前に、手元にあると早いもの」のチェックリストを置き、入力中も見えるよう画面に留めています。薔薇色はこのページでは送信のボタンだけです。個人情報の扱いのページはまだないため、フォームの上に要点を3行置き、【要確認】は見出しに1回だけ付けています
ページの終わり本線はページの終わりで止まり、そこから横に出る点線の支線の先に「迷ったときは」と「費用の考え方を見る」のボタンを置きました。次の駅の「相談」は送ったあとの段階なので、ページの中の3駅で示し、終わりで来た道を戻るように見せないためです

06あえて避けたこと

  • 問い合わせ前に必要な情報が書かれていない
  • メニュー名が英語だけで意味を推測しにくい（ナビは「案内を読む」「相談を申し込む」の2つだけ）
  • 構想の説明が先に立ち、いま何を頼めるのかが分からない
  • 掲載できる事実がないまま、実績や利用者の声を作って載せる
  • 専門用語を説明なしで使うこと（カード決済・ネット予約・読み取り機・回線に言い換えを添えています）
  • 実在のレジ・決済端末・予約サービスの名前や画面に見える表現
  • 「必ず売上が上がる」などの効果の断定
  • 粒の点線・丸ゴシックの極太見出し・厚い影のボタンで「親しみやすさ」を演出すること
  • 料金や表の章を、暗い全面の地にすること

07実際の制作で変わること

  • 図版: カウンター・3つの業態・設定の作業机・用意するもの・オンライン相談の5枚はAI生成のイメージの仮画像で、あとで同じ名前・同じ大きさの画像に差し替えます。3つの業態の図は1枚を3本の駅名板に切り分けているため、差し替える画像も3つの島を横に等間隔に並べます。手元の写真3枚（相談・提案・予約の手元）もAI生成のイメージです。実際の制作では、事業者が撮影した写真に差し替えます
  • 予約画面: 写真の中のスマートフォンの画面は、この見本のための架空の画面です。実際の制作では、事業者が使う予約サービスの画面を、許可を得て載せます
  • ロゴ: 実際の制作では、事業者のロゴを使います（この見本の「てびき舎」の印は見本用の簡易なものです）
  • 価格・受付時間・対応範囲・返信の目安: 事業者が確定した値を載せます
  • 個人情報の扱い: 使う目的・保存の期間・ほかへ渡さないことは【要確認】です。ページを作ってフォームからリンクします
  • 相談フォーム: 事業者が使っているフォームへつなぎます（見本ではダイアログを出すだけで、何も送りません）
  • 書体: 文章を直したら、文字の絞り込みを作り直します
  • 所在地: 見本上の架空の地名を載せています。電話番号は載せていません（連絡は相談フォーム）。実際の制作では、事業者の所在地と連絡先を載せます
